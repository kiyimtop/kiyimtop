# KiyimTop — инструкция для Claude

> **Сначала прочитай [`START_HERE_FOR_AI.md`](START_HERE_FOR_AI.md)** — короткие обязательные правила:
> какую архитектуру не менять, как обновлять правила Firebase и как отдавать работу владельцу.

## О проекте

**KiyimTop** — каталог одежды для Ташкента.

Как это работает для покупателя:
1. Открывает KiyimTop (в браузере, в Telegram или в приложении на телефоне).
2. Выбирает категорию (футболки, куртки, кроссовки и т.д.).
3. Видит магазины, где эта вещь есть в наличии.
4. Выбирает товар (размер, цвет) и **бронирует** его.
5. Приходит в магазин и забирает товар (оплата — в магазине).

Как зарабатывает KiyimTop: магазины платят **подписку** за то, чтобы их товары были в каталоге.

Роли:
- **Покупатель** — смотрит каталог, бронирует товары.
- **Магазин** — добавляет товары, видит и подтверждает брони.
- **Админ (команда KiyimTop)** — управляет магазинами и подписками.

## Три платформы — один код

KiyimTop — **одно** приложение, которое работает в трёх местах:

| # | Платформа | Как открывают | Когда |
|---|---|---|---|
| 1 | **Сайт** | Ссылка в браузере на телефоне или компьютере | Сразу |
| 2 | **Telegram Mini App** | Кнопка «Ochish» в Telegram-боте [@KiyimTopBot](https://t.me/KiyimTopBot) | Работает |
| 3 | **Мобильное приложение** | Сначала **PWA** (сайт, который можно «установить» на главный экран телефона), позже — настоящие приложения для **Android и iOS** через **Capacitor** (инструмент, который упаковывает сайт в приложение для магазинов приложений) | PWA — работает (временная иконка «K»), Capacitor — позже |

### Правила для платформ
- **Один код для всех.** Не делать отдельные версии сайта под каждую платформу.
- **Всё, что связано с Telegram, — только через файл `src/lib/platform.js`.**
  Остальной код не обращается к Telegram напрямую, а спрашивает у этого файла:
  «мы в Telegram?», «какой язык у пользователя?» и т.д.
- **Внутри Telegram** используем его возможности:
  - тему и цвета (шапка и фон под наши цвета);
  - кнопки Telegram (главная кнопка внизу, кнопка «Назад»);
  - вход: пользователь уже известен Telegram, логин и пароль не нужны;
  - язык пользователя из Telegram.
- **В обычном браузере** приложение работает **без Telegram**:
  - обычные кнопки на странице вместо кнопок Telegram;
  - свой способ входа (например, «Войти через Telegram» на сайте или по номеру телефона — решим позже);
  - язык берём из настроек браузера.
- Любая функция Telegram должна иметь **замену для браузера**. Если замены нет — приложение
  не должно ломаться, просто эта функция не показывается.
- Проверять каждое изменение **и в браузере, и в Telegram**.
- Для будущего Capacitor: не использовать то, что работает только на компьютере
  (наведение мышкой как единственный способ что-то открыть и т.п.).

цвет шапки Telegram в `src/lib/platform.js`, `theme-color` в `index.html`
и `background_color` / `theme_color` в `public/manifest.webmanifest` —
при смене цвета фона поменять и там. На оранжевом фоне текст тёмный, на зелёном — белый (так лучше читается).

(3 варианта: вещь, детали, фон) — в `src/components/showcaseArt.js`. На остальных страницах — бежевый.

**Шрифты:** Manrope — основной текст, Unbounded — логотип и крупные заголовки витрины
(подключены в `index.html` из Google Fonts; в CSS — `--font-text` и `--font-display`).

## Правила работы (обязательно)

### 1. Объяснять простым языком на русском
- Владелец проекта — **не программист**. Все объяснения — на русском, без жаргона.
- Если без технического слова не обойтись — сразу объяснить его одной фразой.
- Перед каждым действием коротко сказать: **что** делаю и **зачем**.
- После действия сказать: **что изменилось** (какие файлы создал или поменял).

### 2. Одна задача за раз
- Делать только одну задачу, потом остановиться.
- В конце каждой задачи обязательно написать раздел **«Как проверить»**:
  пошаговая инструкция, что нажать или открыть, и что должно получиться.
- Не начинать следующую задачу, пока владелец не подтвердит.
- Ничего не устанавливать (пакеты, сервисы) без явного разрешения.

### 3. Ключи и пароли — только в `.env`
- Все ключи, токены и пароли хранятся **только** в файле `.env`.
- **Никогда** не писать ключи прямо в коде, в комментариях, в README или в сообщениях коммитов.
- Файл `.env` никогда не попадает на GitHub (он указан в `.gitignore`).
- В репозитории хранится только `.env.example` — список названий переменных **без значений**.
- На Cloudflare ключи вводятся в настройках Worker'а (Settings → Variables and Secrets), а не в коде.
- Важно про Vite: переменные с приставкой `VITE_` попадают в браузер и их может увидеть любой.
  Поэтому с `VITE_` можно только публичные значения (`VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_API_KEY`).
  Секретные ключи (`TELEGRAM_BOT_TOKEN`, `FIREBASE_SERVICE_ACCOUNT`) — **без** `VITE_`,
  и используются только на сервере (`server/`).
- Если владелец случайно прислал ключ в чат или он попал в код — предупредить и предложить заменить ключ.

### 4. Два языка интерфейса
- Интерфейс на **узбекском (латиница)** и **русском**.
- Язык по умолчанию — узбекский. Если у пользователя язык Telegram (или браузера) русский —
  сразу показывать русский. Переключатель **UZ / RU** есть всегда, выбор запоминается.
- **Никакого текста прямо в компонентах.** Все надписи — в файлах переводов
  `src/locales/uz.json` и `src/locales/ru.json`.
- Добавляя новую надпись, всегда добавлять её **в оба** файла.
- Данные товаров (название, описание) в базе тоже хранить на двух языках
  (например, поля `name_uz` и `name_ru`).
- Узбекский — только латиница (o‘, g‘, sh, ch), не кириллица.

### 5. Общие правила кода
- Простой и понятный код важнее «умного».
- Сначала делаем для телефона, потом проверяем, что на компьютере тоже нормально.
- Цены — в сумах (UZS), формат: `150 000 so‘m` / `150 000 сум`.

### 6. Публикация (Cloudflare Workers)
- **Весь код — только в GitHub** (репозиторий `kiyimtop/kiyimtop`). Cloudflare ничего у себя не хранит:
  после каждого изменения в GitHub он сам берёт код, собирает сайт и публикует его вместе с сервером.
- Адрес — https://kiyimtop.kiyimtop.workers.dev, позже — **kiyimtop.uz**.
- Сборка: `npm run build` (папка `dist/`), выкладка: `npx wrangler deploy` (настройки — `wrangler.jsonc`).
- Владелец загружает файлы на GitHub через сайт (Add file → Upload files). Удалить файл или папку —
  только вручную на GitHub (⋯ → Delete file / Delete directory): загрузка ничего не удаляет.
- GitHub Pages, Vercel и Supabase больше не используются (их файлы удалены 12.11.2026).
  Если в настройках GitHub (Settings → Pages) ещё включён сайт — выключить, чтобы не открывали старую версию.
- Перед отправкой на GitHub проверять, что проект собирается (`npm run build`).

### 7. PWA (установка на телефон)
- «Паспорт» приложения — `public/manifest.webmanifest`, помощник — `public/sw.js`.
- Помощник всегда сначала берёт свежую версию из интернета, сохранённая копия — только без интернета.
  Включается только в готовой версии сайта и **не** в Telegram.
- При изменении `public/sw.js` увеличивать номер версии `CACHE` (например, `kiyimtop-v2`).
- **Смена иконки:** заменить `public/icons/icon.svg` (полный квадрат, для iPhone и вкладки),
  `public/icons/icon-maskable.svg` (то же, но рисунок в центральных 80% — Android обрезает в круг)
  и `public/favicon.svg`, затем заново сделать PNG: `icon-192.png`, `icon-512.png`,
  `icon-maskable-512.png` (512×512) и `apple-touch-icon.png` (180×180).

### 8. База данных (Firebase / Firestore) — как в TheStarth (с 13.11.2026)
- **Сайт сам читает и пишет в базу** через библиотеку `firebase` (`firebase/app`, `firebase/auth`,
  `firebase/firestore`; грузится отдельно после главной — `src/lib/fb.js`). Кто что может — решают
  **правила доступа** `firebase/firestore.rules` (как в TheStarth). Сервера с ключом для этого не нужно:
  раньше без секрета `FIREBASE_SERVICE_ACCOUNT` вход, брони, кабинет и админка писали «скоро заработает».
- Тариф бесплатный (Spark), без карты. Регион базы — **europe-west**.
- **Каталог** по-прежнему читается без библиотеки, по адресу Firestore: `src/lib/firebase.js` (`readCollection`),
  все запросы каталога — в `src/lib/catalog.js` (весь каталог одним разом, запоминается на 2 минуты).
- **Где какой код:** `src/lib/db.js` — помощники базы (даты → текст ISO, ошибки → наши коды);
  `src/lib/auth.js` — вход, регистрация, профиль; `src/lib/bookings.js` — брони; `src/lib/seller.js` — кабинет
  магазина; `src/lib/admin.js` — админ-панель; `src/lib/notify.js` — просьба серверу написать в бот.
- **Правила доступа** — `firebase/firestore.rules`. Владелец вставляет файл: Firestore Database → Rules → Publish.
  Меняем правила — меняем этот файл и даём владельцу текст в чате. Коротко, что в них:
  - `users` — свой профиль читает и меняет сам человек (имя, фамилия, телефон); роль и блокировку — только админ
    (модератор — только блокировку покупателей/продавцов); Telegram пишет сервер бота, человек может только отвязать.
  - `categories`, `settings` — читают все; меняют админ и модератор (`settings` — только админ).
  - `shops` — все видят активные; заявку подаёт вошедший незаблокированный (только pending и скрытый);
    владелец меняет только данные магазина; статус, подписку, владельцев — админ/модератор.
  - `products` — меняет владелец одобренного магазина и админ/модератор. Покупатель может только
    забрать 1 штуку варианта вместе с созданием своей брони (`hold_op: take`) или вернуть её вместе с отменой/истечением (`give`).
    Поля `hold_ref` (номер брони), `hold_op`, `hold_idx` (номер варианта) — служебные, для этой проверки.
  - `bookings` — создаёт покупатель с подтверждённым email; видят покупатель, владельцы магазина (копия
    `owner_uids` в брони) и админ/модератор; покупатель отменяет; магазин подтверждает / нет в наличии / выдан.
  - `payments` (оплаты подписок) — админ/модератор; `admin_log` (журнал) — дописывает админ/модератор, читает админ, менять нельзя.
  - Все запросы — по одному полю (`where`), составные индексы не нужны.
- **Бронь** (`src/lib/bookings.js`): транзакция — товар −1 и запись брони вместе. «Не больше 3 действующих»
  и «один вариант — одна бронь» проверяет сайт (правила этого не умеют; нарушителя админ блокирует).
  Отмена и истечение (2 дня) возвращают +1. Будильника нет: просроченные брони отпускаются, когда их
  открывает покупатель («Мои брони»), магазин (кабинет) или админ (вкладка «Брони»).
  Подписка магазина: закончилась — магазин скрывается, когда открывают кабинет или админку.
- **Тестовые данные** «(demo)» удаляются в админ-панели → «Магазины» → внизу «Удалить тестовые данные».
  Новая категория — в админ-панели → «Каталог» → «Новая категория» (рисунок — в `showcaseArt.js` по желанию).
- Настройки (публичные, `VITE_`): `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_API_KEY` — из
  Firebase → Project settings → Your apps → firebaseConfig. На Cloudflare — Settings → Build → Variables.
- Проверка без интернета: Claude собирает сайт с поддельным Firebase в памяти и прогоняет сценарии
  в браузере (держит у себя, в проект не входит). Правила так проверить нельзя — их проверяет Firebase при Publish.

### 8б. Cloudflare Worker
- `wrangler.jsonc` и `server/worker.js`: `/api/*` → сервер, остальное — файлы из `dist`
  (`not_found_handling: single-page-application`). Сборка: `npm run build`, выкладка: `npx wrangler deploy`.
- В `wrangler.jsonc` — `FIREBASE_PROJECT_ID` (публичный номер проекта, для проверки входа при загрузке фото)
  и `keep_vars: true` (не стирать переменные из панели Cloudflare).
- **Сервер теперь нужен только Telegram-боту:** `/api/photo` (фото товаров), `/api/notify` (сообщения о бронях
  и заявках), `/api/bot-webhook`, `/api/bot-setup`, `/api/account` (привязка Telegram), `/api/tg-signin`.
  Секреты (Settings → Variables and Secrets), все необязательные — сайт работает и без них:
  - `TELEGRAM_BOT_TOKEN` — бот и фото товаров;
  - `TELEGRAM_STORAGE_CHAT_ID` — куда бот складывает фото (иначе — в Telegram самого продавца);
  - `FIREBASE_SERVICE_ACCOUNT` — чтобы бот присылал сообщения о бронях/заявках, привязывал Telegram и
    кнопки в боте работали. Без него сайт работает полностью, просто бот молчит.
- GitHub Pages **не используется**: старая копия на `kiyimtop.github.io/kiyimtop` — выключить
  (GitHub → Settings → Pages → Unpublish / Source: None), иначе люди попадают на старый сайт без входа.

### 8а. Сторона магазина и админка
- **Идея платформы:** один и тот же товар (например, конкретная футболка) продаётся в разных магазинах —
  у их записей общий `model_id`. На странице товара блок «Ещё в других магазинах» — где есть и почём.
  Магазин, добавляя товар, ищет его в каталоге («Этот товар уже есть в других магазинах?») и привязывается.
- **Магазины добавляют товары сами, но только после разрешения админа.** Поля магазина: `owner_uids`,
  `owner_lang`, `status` (pending → active / rejected / blocked), `is_active`, `subscription_until`
  (пусто — без срока; после одобрения — пробные 30 дней). Покупатели видят магазин, только если `is_active`.
- **Кабинет магазина** — `/my-shop` (сайт и Mini App; в боте `/shop`): заявка, брони (подтвердить / нет
  в наличии / выдан), товары (редактор), данные магазина. Код — `src/pages/SellerCabinet.jsx`, `src/lib/seller.js`.
- **Админ-панель** — `/admin` (`src/pages/Admin.jsx`, `src/lib/admin.js`), для админа и модератора. Вкладки:
  «Аналитика» (пользователи по ролям, магазины, товары, брони, доход от подписок по месяцам, цена подписки),
  «Магазины» (заявки, +30 дней с суммой оплаты → `payments`, владельцы по email, блокировка, кабинет любого магазина),
  «Пользователи» (поиск по имени/email/телефону, роли — только админ, блокировка),
  «Каталог» (категории: добавить/изменить/удалить пустую; все товары: скрыть/показать/удалить),
  «Брони» (все брони: отменить, удалить), «Журнал» (только админ: кто что сделал — `admin_log`).
  Можно открыть сразу нужную вкладку: `/admin?tab=analytics`. Отзывов пока нет — их удаление добавить сюда, когда появятся.
- **Бот:** новая бронь → владельцам магазина сообщение с кнопками; ответ магазина → покупателю;
  заявка магазина → админам и модераторам с кнопками «Разрешить / Отклонить» (нужен `FIREBASE_SERVICE_ACCOUNT`).
  Сайт просит сервер `/api/notify`, сервер сам перепроверяет запись в базе и пишет один раз (отметки `notified_*`).
- **Фото товаров хранятся в Telegram:** кабинет уменьшает фото до 1280 px, сервер отправляет его в служебный
  чат (`TELEGRAM_STORAGE_CHAT_ID`, иначе — Telegram продавца), в товаре хранится `/api/photo?id=<file_id>`.
  Сервер проверяет вход и права «от имени человека» (его ID-токен + правила), без ключа сервисного аккаунта.

### 8в. Аккаунты и роли (с 13.11.2026 — как в TheStarth)
- **Вход:** Google или email + пароль. **Регистрация:** имя, фамилия, телефон (+998, поле `components/PhoneInput.jsx`),
  email и пароль; потом письмо для подтверждения email. Вошли через Google без телефона — профиль просит его дописать.
- Профиль `users/<uid>` создаёт сам сайт при первом входе: email, name, surname, phone («+998901234567»),
  role, blocked, lang, created_at; Telegram-поля пишет сервер бота. Код — `src/lib/auth.js`, экраны —
  `AuthForm.jsx`, `VerifyEmail.jsx`, `pages/Account.jsx`.
- **Роли** (`role`): `admin` — всё; `moderator` — магазины, каталог, брони, блокировка покупателей/продавцов;
  `seller` — ставится сама, когда магазин одобрен; пусто — покупатель. Себя менять нельзя.
- **Первый админ** — владелец ставит себе сам: зарегистрироваться на сайте → Firebase → Firestore → `users` →
  свой документ (по email) → поле `role` = `admin` (тип string). Дальше роли выдаются в админ-панели.
  `ADMIN_EMAILS` на Cloudflare сайту больше не нужен (бот его ещё понимает).
- **Блокировка:** заблокированный не может бронировать и подавать заявки; его действующие брони отменяются.
- **Бронировать можно только с подтверждённым email** (правила проверяют `email_verified` во входе Firebase).
- **Telegram** привязывается через бота (профиль → «Привязать Telegram») или в Mini App одной кнопкой —
  работает, когда на Cloudflare есть `TELEGRAM_BOT_TOKEN` и `FIREBASE_SERVICE_ACCOUNT`. Отвязать можно всегда.
- **Настройка (один раз):** Firebase → Authentication → Sign-in method: включить **Google** и **Email/Password**;
  Settings → Authorized domains: добавить адрес сайта (`kiyimtop.kiyimtop.workers.dev`, позже `kiyimtop.uz`).

### 9. Страницы и навигация
- Адреса страниц — в `src/lib/router.jsx`, без отдельной библиотеки:
  `/` — главная, `/c/<slug>` — категория (например `/c/sneakers`),
  `/c/<slug>/p/<id>` — товар, `/s/<id>` — магазин, `/search?q=…` — поиск. Новые страницы добавлять туда же.
- Переходы внутри приложения — только через `<Link to="…">` или `navigate()` (без перезагрузки).
- «Назад» — компонент `BackButton`: в Telegram показывает кнопку Telegram в шапке,
  в браузере — кнопку на странице. Если страницу открыли по прямой ссылке — ведёт на уровень выше.
- Ссылки на внешние сайты (карта, Telegram магазина) — только через `ExternalLink`:
  в Telegram они открываются через Telegram, в браузере — в новой вкладке.
- Цена — только через `formatPrice()` из `useI18n()`: «549 000 so‘m» / «549 000 сум».
- Числа в надписях — через подстановку: `t('product.inStock', { n: 3 })` → «В наличии: 3 шт.»
- Карта магазина — Яндекс Карты по координатам (`latitude`, `longitude`).
- **Вид страниц категории и товара — как у витрины** (владелец: «не должно выглядеть дёшево»):
  фон в цвете категории, выбранном на витрине (`lib/choices.js` → `lib/pageColor.js`),
  заголовки шрифтом Unbounded, белые карточки со скруглением 24–28 px, значки — `components/Icon.jsx`
  (не эмодзи), кнопки-«таблетки» `.chip` как на витрине.
- Пока у товара нет фото от магазина — вместо фото **рисунок категории в цвете товара**
  (`itemHTML` в `showcaseArt.js`). Цвета товаров по названию — `src/lib/colors.js`
  (новый цвет в базе → добавить туда).
- Магазины в категории — сначала дешевле, «Дешевле всего» — у магазина с самой низкой ценой;
  «Открыто до …» / «Закрыто» — по ташкентскому времени (`lib/hours.js`, `components/OpenStatus.jsx`).
- **Фильтры и сортировка** на странице категории: кнопки «Фильтры» (цифра — сколько выбрано)
  и «Сортировка» над списком, размеры — «таблетками» на самой странице.
  - Фильтры: для кого (мужское/женское/детское; «унисекс» подходит и мужчинам, и женщинам),
    цена («от»/«до» + 3 быстрые кнопки по ценам категории), цвет, бренд, район, «Открыто сейчас».
    Показываются только варианты, которые есть в этой категории. Выбор применяется сразу.
  - Сортировка: «Сначала дешёвые» (обычная), «Сначала дорогие», «Сначала ближе» (показывает расстояние).
    «Самые популярные» и «С высоким рейтингом» — после бронирования и отзывов (сейчас данных нет —
    не показываем ненастоящие).
  - Выбор хранится в адресе (`/c/sneakers?gender=men&color=Qora&sort=near`): при возврате со страницы
    товара всё на месте. Размер и цвет передаются на страницу товара (`?size=42&color=Qora`).
  - «Сначала ближе»: место пользователя — `getUserLocation()` в `platform.js` (в Telegram — его
    LocationManager, в браузере — запрос браузера). Координаты **никуда не отправляются**:
    расстояние считается на телефоне. Не разрешил — сообщение и прежняя сортировка.
  - Код: `lib/filters.js` (что подходит, адрес), `components/CategoryFilters.jsx` (шторки).
- **Поиск** — лупа в шапке на всех страницах (кроме самого поиска) → `/search`.
  Ищет категории, магазины (название, адрес, ориентир, район) и товары (название uz/ru, бренд,
  категория, цвета в наличии) **сразу на обоих языках**. Понимает: заглавные/строчные, ё/е,
  апострофы (`ko'ylak` = `koylak` = `ko‘ylak`), узбекский кириллицей (`кўйлак` → `ko‘ylak`),
  другие формы слова (`кроссовок` → `кроссовки`). Цвет из запроса («qora krossovka») —
  вещь показывается и открывается в этом цвете. Запрос — в адресе (при «Назад» результаты на месте).
  Ищем на телефоне по списку из `fetchSearchIndex()` (`lib/search.js`); когда товаров станут
  тысячи — перенести поиск в базу.
- **Страница магазина** `/s/<id>`: название, описание, адрес, часы, «Позвонить», карта, Telegram
  и все товары по категориям (кнопки сверху — одна категория, `?c=sneakers`). Фон бежевый.
  Открывается из поиска, по названию магазина на странице категории и из блока «Где купить» у товара.
- Общие детали: строка товара — `components/ProductRow.jsx` (категория, поиск, магазин),
  адрес/часы/кнопки магазина — `components/ShopInfo.jsx` (товар, магазин).
- Шторки снизу (меню категорий, фильтры, сортировка) — один компонент `components/Sheet.jsx`.
  В Telegram его «Назад» при открытой шторке закрывает только шторку (`setTelegramBackButton` в
  `platform.js` помнит, кто открыт последним).
- «Забронировать» на телефоне прилипает к низу экрана.
- **Бронь** (`components/BookingSheet.jsx`, `pages/MyBookings.jsx` — `/bookings`, `lib/bookings.js`):
  - «Забронировать» → шторка (что, цвет · размер, цена, магазин, «держится 2 дня — до …»)
    → «Забронировано!» и **код брони** (покупатель показывает его в магазине).
  - Не вошли — прямо в шторке вход или регистрация (`components/AuthForm.jsx`); email не подтверждён —
    «Подтвердите email» (`components/VerifyEmail.jsx`). Подробно — раздел «Аккаунты».
  - Правила (на сервере, транзакция): не больше **3** действующих броней у аккаунта; один вариант — одна бронь;
    бронь уменьшает количество на 1, отмена и истечение (2 дня) — возвращают.
  - «Мои брони» — меню «⋮» → «Мои брони» и после брони; сначала действующие; отмена — с подтверждением.
  - Ссылка `t.me/KiyimTopBot?startapp=bookings` открывает «Мои брони», `?startapp=<slug>__<id товара>` — товар,
    `?startapp=book__<id варианта>` — товар с подтверждением брони (`fetchVariant()` в `catalog.js`)
    (нужен включённый **главный Mini App** бота: @BotFather → `/mybots` → бот → Bot Settings →
    Configure Mini App → Enable Mini App → адрес сайта; без этого Telegram показывает ошибку `BOT_INVALID`).
- **Сервер** — папка `server/`, работает на Cloudflare Workers, нужен только боту и фото:
  - `server/worker.js` — главный файл: адреса `/api/…` → обработчики, остальное — страницы сайта;
  - `server/accounts.js` — проверка входа (ID-токен Firebase), привязка Telegram `/api/account`,
    вход в Mini App `/api/tg-signin`, кто админ (для бота);
  - `server/handlers.js` — бот `/api/bot-webhook` (сюда Telegram присылает всё, что пишут боту; проверяет секрет
    Telegram, отвечает всегда 200), `/api/bot-setup` (подключить бота — один раз открыть на основном адресе);
  - `server/notify.js` — `/api/notify`: сайт просит написать в бот о брони/заявке, сервер перепроверяет по базе;
  - `server/seller.js` — кнопки брони и заявок в боте, сообщения владельцам/покупателям, фото `/api/photo`;
  - `server/telegram.js` — проверка Mini App (`verifyInitData`, 7 дней), секрет бота, вызовы Telegram.
    Шифрование — WebCrypto (`crypto.subtle`): работает и в Cloudflare, и в Node;
  - `server/firestore.js` — доступ к базе от имени сервисного аккаунта;
  - `server/bot-texts.js` — сообщения бота uz/ru (сервер не читает `src/locales`; узбекский — латиница);
  - `server/run.js` — переходник: обработчик → ответ Cloudflare. Новый адрес `/api/…` = обработчик + строка в `worker.js`.
  - Адрес сайта для бота — `SITE_HOST` из настроек или адрес, на который пришёл запрос.
  Сайт присылает в заголовке `Authorization: Bearer <ID-токен Firebase>` (`authHeader()` в `lib/auth.js`).
  Без ключей бот молчит, а сайт работает полностью (кроме загрузки фото — для неё нужен `TELEGRAM_BOT_TOKEN`).

### 11. Telegram-бот
- Бот: **@KiyimTopBot** (https://t.me/KiyimTopBot), создан через @BotFather.
- Кнопка меню **«Ochish»** открывает Mini App по адресу https://kiyimtop.kiyimtop.workers.dev (ставит `/api/bot-setup`).
  Тот же адрес — у **главного Mini App** (Bot Settings → Configure Mini App): он нужен ссылкам
  `t.me/KiyimTopBot?startapp=…` с сайта. При смене адреса (например, на kiyimtop.uz) поменять его
  в @BotFather в обоих местах: `/mybots` → бот → Bot Settings → Menu Button и Configure Mini App.
- **Бот отвечает на сообщения** через `/api/bot-webhook`. Подключение — один раз открыть
  `https://<основной адрес>/api/bot-setup` (страница напишет «Бот подключён»). При каждой смене адреса
  (например, на kiyimtop.uz) открыть `/api/bot-setup` на новом адресе. Пока бот не подключён, он молчит.
- Команды: /start, /bookings, /account, /shop (и /admin — только админам с привязанным Telegram).
- **Токен бота** хранится только у владельца. Никогда не просить его в чат и не писать в код.
  Владелец сам вписывает его в Cloudflare: Settings → Variables and Secrets → `TELEGRAM_BOT_TOKEN` (Secret).
  Если токен попал не туда — `/revoke` в @BotFather.

### Коллекции в базе (Firestore)
- `categories` — категории: id = slug, названия uz/ru, эмодзи, `sort_order`. Меняются в админ-панели → «Каталог».
- `shops` — магазины: название, описание/адрес/ориентир uz/ru, координаты, телефон, Telegram, часы,
  `district`, `owner_uids`, `owner_lang`, `status`, `is_active`, `subscription_until` (+ служебные `notified_*`).
- `products` — товары: `shop_id`, `category_id`, `model_id`, названия uz/ru, бренд, для кого, цена в сумах,
  `photo_urls`, `is_active`, `variants` (id, size, color_uz/ru, quantity), служебные `hold_ref`/`hold_op`/`hold_idx`.
- `bookings` — брони: `user_id`, `owner_uids` (копия владельцев магазина), товар и вариант + копия названия/цвета/
  размера/цены и магазина, `buyer_name`, `buyer_phone`, `buyer_email`, статус (`new` / `confirmed` / `picked_up` /
  `cancelled` / `unavailable` / `expired`), `expires_at` (2 дня), `code` (+ служебные `notified_*`).
- `users` — профили: email, name, surname, phone, `role`, `blocked`, lang, created_at, привязанный Telegram.
- `payments` — оплаты подписок (сумма, дни, магазин, когда) — для «Аналитики».
- `admin_log` — журнал действий админов и модераторов.
- `settings/main` — настройки (`subscription_price` — цена подписки в месяц).
- `tg_links` — ссылки для привязки Telegram (только сервер, 10 минут).

## Команды
- `npm install` — установить библиотеки (нужно один раз после скачивания проекта)
- `npm run dev` — запустить приложение на своём компьютере
- `npm run build` — собрать версию для публикации (папка `dist/`)
- `npm run preview` — посмотреть собранную версию на своём компьютере
