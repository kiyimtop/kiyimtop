# KiyimTop — инструкция для Claude

## О проекте

**KiyimTop** — каталог одежды для Ташкента.

Как это работает для покупателя:
1. Открывает KiyimTop (в браузере, в Telegram или в приложении на телефоне).
2. Выбирает категорию (футболки, куртки, кроссовки и т.д.).
3. Видит магазины, где эта вещь есть в наличии.
4. Выбирает товар (размер, цвет) и **бронирует** его.
5. Приходит в магазин и забирает товар (оплата — в магазине).

Как зарабатывает KiyimTop: магазины платят **подписку** за то, чтобы их товары были в каталоге.

Роли:
- **Покупатель** — смотрит каталог, бронирует товары.
- **Магазин** — добавляет товары, видит и подтверждает брони.
- **Админ (команда KiyimTop)** — управляет магазинами и подписками.

## Три платформы — один код

KiyimTop — **одно** приложение, которое работает в трёх местах:

| # | Платформа | Как открывают | Когда |
|---|---|---|---|
| 1 | **Сайт** | Ссылка в браузере на телефоне или компьютере | Сразу |
| 2 | **Telegram Mini App** | Кнопка «Ochish» в Telegram-боте [@KiyimTopBot](https://t.me/KiyimTopBot) | Работает |
| 3 | **Мобильное приложение** | Сначала **PWA** (сайт, который можно «установить» на главный экран телефона), позже — настоящие приложения для **Android и iOS** через **Capacitor** (инструмент, который упаковывает сайт в приложение для магазинов приложений) | PWA — работает (временная иконка «K»), Capacitor — позже |

### Правила для платформ
- **Один код для всех.** Не делать отдельные версии сайта под каждую платформу.
- **Всё, что связано с Telegram, — только через файл `src/lib/platform.js`.**
  Остальной код не обращается к Telegram напрямую, а спрашивает у этого файла:
  «мы в Telegram?», «какой язык у пользователя?» и т.д.
- **Внутри Telegram** используем его возможности:
  - тему и цвета (шапка и фон под наши цвета);
  - кнопки Telegram (главная кнопка внизу, кнопка «Назад»);
  - вход: пользователь уже известен Telegram, логин и пароль не нужны;
  - язык пользователя из Telegram.
- **В обычном браузере** приложение работает **без Telegram**:
  - обычные кнопки на странице вместо кнопок Telegram;
  - свой способ входа (например, «Войти через Telegram» на сайте или по номеру телефона — решим позже);
  - язык берём из настроек браузера.
- Любая функция Telegram должна иметь **замену для браузера**. Если замены нет — приложение
  не должно ломаться, просто эта функция не показывается.
- Проверять каждое изменение **и в браузере, и в Telegram**.
- Для будущего Capacitor: не использовать то, что работает только на компьютере
  (наведение мышкой как единственный способ что-то открыть и т.п.).

## Правила работы (обязательно)

### 1. Объяснять простым языком на русском
- Владелец проекта — **не программист**. Все объяснения — на русском, без жаргона.
- Если без технического слова не обойтись — сразу объяснить его одной фразой.
- Перед каждым действием коротко сказать: **что** делаю и **зачем**.
- После действия сказать: **что изменилось** (какие файлы создал или поменял).

### 2. Одна задача за раз
- Делать только одну задачу, потом остановиться.
- В конце каждой задачи обязательно написать раздел **«Как проверить»**:
  пошаговая инструкция, что нажать или открыть, и что должно получиться.
- Не начинать следующую задачу, пока владелец не подтвердит.
- Ничего не устанавливать (пакеты, сервисы) без явного разрешения.

### 3. Ключи и пароли — только в `.env`
- Все ключи, токены и пароли хранятся **только** в файле `.env`.
- **Никогда** не писать ключи прямо в коде, в комментариях, в README или в сообщениях коммитов.
- Файл `.env` никогда не попадает на GitHub (он указан в `.gitignore`).
- В репозитории хранится только `.env.example` — список названий переменных **без значений**.
- На Vercel ключи вводятся в настройках проекта (Settings → Environment Variables), а не в коде.
- Важно про Vite: переменные с приставкой `VITE_` попадают в браузер и их может увидеть любой.
  Поэтому с `VITE_` можно только публичные значения (адрес Supabase, публичный ключ Supabase —
  **publishable**, раньше назывался `anon`).
  Секретные ключи (`SUPABASE_SECRET_KEY` — раньше `service_role`, `TELEGRAM_BOT_TOKEN`) — **без** `VITE_`,
  и используются только на сервере (папка `api/` на Vercel).
- Если владелец случайно прислал ключ в чат или он попал в код — предупредить и предложить заменить ключ.

### 4. Два языка интерфейса
- Интерфейс на **узбекском (латиница)** и **русском**.
- Язык по умолчанию — узбекский. Если у пользователя язык Telegram (или браузера) русский —
  сразу показывать русский. Переключатель **UZ / RU** есть всегда, выбор запоминается.
- **Никакого текста прямо в компонентах.** Все надписи — в файлах переводов
  `src/locales/uz.json` и `src/locales/ru.json`.
- Добавляя новую надпись, всегда добавлять её **в оба** файла.
- Данные товаров (название, описание) в базе тоже хранить на двух языках
  (например, поля `name_uz` и `name_ru`).
- Узбекский — только латиница (o‘, g‘, sh, ch), не кириллица.

### 5. Общие правила кода
- Простой и понятный код важнее «умного».
- Сначала делаем для телефона, потом проверяем, что на компьютере тоже нормально.
- Цены — в сумах (UZS), формат: `150 000 so‘m` / `150 000 сум`.

  команда `npm run build`, папка `dist`, версия Node — из файла `.node-version` (22).
  Адрес — `<проект>.pages.dev` (точный адрес записать сюда после создания проекта), позже — **kiyimtop.uz**.
- **Сейчас (с 06.11.2026)** сайт на GitHub — **готовая сборка в папке `docs/`**: Settings → Pages →
  Deploy from a branch → `main`, папка `/docs`. Сборку делает Claude (`BASE_PATH=/kiyimtop/` и настройки Firebase),
  владелец загружает папку. Адрес: https://kiyimtop.github.io/kiyimtop/. `pages.yml` — только вручную.
- **GitHub Pages через Actions** (запасной способ): https://qnn975.github.io/Topdim/ — сайт без серверной части
  (бронь и вход через бота там пишут «скоро заработает»). Собирает GitHub сам: `.github/workflows/pages.yml`

- Ветка `main` — **основная версия** (её видят все пользователи). Каждая другая ветка и каждый

- Без отдельного сервиса «засыпания» нет: Supabase бесплатный «засыпает» через неделю без посетителей —
  если сайтом пользуются, не заснёт; иначе разбудить в панели Supabase.
- Перед отправкой на GitHub проверять, что проект собирается (`npm run build`).

### 7. PWA (установка на телефон)
- «Паспорт» приложения — `public/manifest.webmanifest`, помощник — `public/sw.js`.
- Помощник всегда сначала берёт свежую версию из интернета, сохранённая копия — только без интернета.
  Включается только в готовой версии сайта и **не** в Telegram.
- При изменении `public/sw.js` увеличивать номер версии `CACHE` (например, `kiyimtop-v2`).
- **Смена иконки:** заменить `public/icons/icon.svg` (полный квадрат, для iPhone и вкладки),

  `icon-maskable-512.png` (512×512) и `apple-touch-icon.png` (180×180).

### 8. База данных (Firebase / Firestore)
- **С 06.11.2026 база — Firebase (Firestore)**, решение владельца (раньше была Supabase; старые файлы
  удалены). Тариф бесплатный (Spark), без карты. Регион базы — **europe-west** (ближе к Ташкенту).
- Сайт читает базу **напрямую по адресу Firestore**, без библиотеки: `src/lib/firebase.js`
  (`readCollection`, `writeDocuments`). Все запросы к каталогу — в `src/lib/catalog.js`, экраны к базе не обращаются.
  Пока товаров мало, каталог загружается целиком одним разом (запоминается на 2 минуты).
- Коллекции: `categories` (id = slug), `shops` (`is_active`, `district` …), `products`
  (`shop_id`, `category_id` = slug, `is_active`, внутри `variants`: id, size, color_uz/ru, quantity).
  Поля — те же, что были в Supabase (`name_uz`/`name_ru` …), поэтому экраны не менялись.
- **Правила доступа** — `firebase/firestore.rules`: посетители только читают категории, активные магазины
  и товары; остальное — только сервер. Владелец вставляет файл: Firestore Database → Rules → Publish.
  Меняем правила — меняем этот файл и даём владельцу текст в чате.
- **Тестовые данные** — `src/seed/demoData.json` (11 категорий, 8 магазинов «(demo)», товары; id магазинов
  `d0000000-0000-4000-8000-…`). Загружаются страницей **`/seed`** (кнопка «Загрузить»), только пока база
  в тестовом режиме; после правил запись оттуда запрещена. Перед запуском для покупателей — удалить
  тестовые магазины (в Firebase: Firestore Database → Data → документ → Delete).
- Настройки (публичные, `VITE_`): `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_API_KEY` — из
  Firebase → Project settings → Your apps → firebaseConfig. На GitHub — Variables (см. `pages.yml`).
- **Сервер тоже на Firebase (с 06.11.2026):** брони (`bookings`) и вход через бота (`login_requests`) —
  `server/handlers.js`, доступ к базе — `server/firestore.js` (ключ сервисного аккаунта, секрет
  `FIREBASE_SERVICE_ACCOUNT` на Cloudflare; правила его не ограничивают, посетители эти коллекции не видят).
  Запросы сервера — только по одному полю (`where`), чтобы не нужны были составные индексы; сортировка — в коде.
- **Бронь:** транзакция — проверка (не больше 3 действующих, не дважды один вариант), `quantity − 1`
  у варианта товара, запись брони с копией данных магазина. Отмена и истечение срока (2 дня) возвращают
  `quantity + 1`. Отдельного «будильника» нет: просроченные брони отпускаются при каждом обращении к `/api/bookings`.
- Проверка сервера без интернета: тест с поддельной базой (Claude держит его у себя, в проект не входит).

### 8б. Cloudflare: Worker (основной вариант) или Pages
- Cloudflare сейчас по умолчанию создаёт **Worker**. Для него — `wrangler.jsonc` и `server/worker.js`:
  `/api/*` → сервер, остальное — файлы из `dist` (`not_found_handling: single-page-application`).
  Сборка: `npm run build`, выкладка: `npx wrangler deploy`. `name` в wrangler.jsonc = название Worker'а.
- Переменные `VITE_…` нужны **при сборке** (Settings → Build → Variables), секреты сервера — в Settings →
  Variables and Secrets (появляются после первой выкладки с `wrangler.jsonc`).
- Папка `functions/` — тот же сервер для варианта Cloudflare Pages.

### 8а. Сторона магазина и админка (с 10.11.2026)
- **Идея платформы:** один и тот же товар (например, конкретная футболка) продаётся в разных магазинах —
  у их записей общий `model_id`. На странице товара блок «Ещё в других магазинах» — где есть и почём.
  Магазин, добавляя товар, ищет его в каталоге («Этот товар уже есть в других магазинах?») и привязывается.
- **Магазины добавляют товары сами, но только после разрешения админа.** Поля магазина: `owner_ids`
  (Telegram ID владельцев), `owner_lang`, `status` (pending → active / rejected / blocked), `is_active`,
  `subscription_until` (пусто — без срока; после одобрения — пробные 30 дней). Покупатели видят магазин,
  только если `is_active`: статус active и подписка не закончилась (сервер выключает просроченные сам).
- **Кабинет магазина** — `/my-shop` (сайт и Mini App; в боте `/shop`): заявка, брони (подтвердить / нет
  в наличии / выдан), товары (редактор: категория, названия, бренд, цена, фото, размеры/цвета/количество),
  данные магазина. **Админка** — `/admin` (в боте `/admin`): заявки, блокировка, +30 дней, владельцы,
  вход в кабинет любого магазина. Админы — `ADMIN_TELEGRAM_IDS` на Cloudflare.
- **Бот:** новая бронь → владельцам магазина сообщение с кнопками; ответ магазина → сообщение покупателю;
  заявка магазина → админам с кнопками «Разрешить / Отклонить».
- **Фото товаров хранятся в Telegram:** кабинет уменьшает фото до 1280 px, сервер отправляет его в служебный
  чат (`TELEGRAM_STORAGE_CHAT_ID`, по умолчанию — первый админ), в товаре хранится `/api/photo?id=<file_id>`;
  сайт показывает фото через этот адрес (Cloudflare запоминает). Без карты и без Firebase Storage.
- Код: сервер — `server/seller.js` (+ `functions/api/me|shop|admin|photo.js`), сайт — `src/lib/seller.js`,
  `src/pages/SellerCabinet.jsx`, `src/pages/Admin.jsx`.

### 9. Страницы и навигация
- Адреса страниц — в `src/lib/router.jsx`, без отдельной библиотеки:
  `/` — главная, `/c/<slug>` — категория (например `/c/sneakers`),
  `/c/<slug>/p/<id>` — товар, `/s/<id>` — магазин, `/search?q=…` — поиск. Новые страницы добавлять туда же.
- Переходы внутри приложения — только через `<Link to="…">` или `navigate()` (без перезагрузки).
- «Назад» — компонент `BackButton`: в Telegram показывает кнопку Telegram в шапке,
  в браузере — кнопку на странице. Если страницу открыли по прямой ссылке — ведёт на уровень выше.
- Ссылки на внешние сайты (карта, Telegram магазина) — только через `ExternalLink`:
  в Telegram они открываются через Telegram, в браузере — в новой вкладке.
- Цена — только через `formatPrice()` из `useI18n()`: «549 000 so‘m» / «549 000 сум».
- Числа в надписях — через подстановку: `t('product.inStock', { n: 3 })` → «В наличии: 3 шт.»
- Карта магазина — Яндекс Карты по координатам (`latitude`, `longitude`).
- **Вид страниц категории и товара — как у витрины** (владелец: «не должно выглядеть дёшево»):
  фон в цвете категории, выбранном на витрине (`lib/choices.js` → `lib/pageColor.js`),
  заголовки шрифтом Unbounded, белые карточки со скруглением 24–28 px, значки — `components/Icon.jsx`
  (не эмодзи), кнопки-«таблетки» `.chip` как на витрине.
- Пока у товара нет фото от магазина — вместо фото **рисунок категории в цвете товара**
  (`itemHTML` в `showcaseArt.js`). Цвета товаров по названию — `src/lib/colors.js`
  (новый цвет в базе → добавить туда).
- Магазины в категории — сначала дешевле, «Дешевле всего» — у магазина с самой низкой ценой;
  «Открыто до …» / «Закрыто» — по ташкентскому времени (`lib/hours.js`, `components/OpenStatus.jsx`).
- **Фильтры и сортировка** на странице категории: кнопки «Фильтры» (цифра — сколько выбрано)
  и «Сортировка» над списком, размеры — «таблетками» на самой странице.
  - Фильтры: для кого (мужское/женское/детское; «унисекс» подходит и мужчинам, и женщинам),
    цена («от»/«до» + 3 быстрые кнопки по ценам категории), цвет, бренд, район, «Открыто сейчас».
    Показываются только варианты, которые есть в этой категории. Выбор применяется сразу.
  - Сортировка: «Сначала дешёвые» (обычная), «Сначала дорогие», «Сначала ближе» (показывает расстояние).
    «Самые популярные» и «С высоким рейтингом» — после бронирования и отзывов (сейчас данных нет —
    не показываем ненастоящие).
  - Выбор хранится в адресе (`/c/sneakers?gender=men&color=Qora&sort=near`): при возврате со страницы
    товара всё на месте. Размер и цвет передаются на страницу товара (`?size=42&color=Qora`).
  - «Сначала ближе»: место пользователя — `getUserLocation()` в `platform.js` (в Telegram — его
    LocationManager, в браузере — запрос браузера). Координаты **никуда не отправляются**:
    расстояние считается на телефоне. Не разрешил — сообщение и прежняя сортировка.
  - Код: `lib/filters.js` (что подходит, адрес), `components/CategoryFilters.jsx` (шторки).
- **Поиск** — лупа в шапке на всех страницах (кроме самого поиска) → `/search`.
  Ищет категории, магазины (название, адрес, ориентир, район) и товары (название uz/ru, бренд,
  категория, цвета в наличии) **сразу на обоих языках**. Понимает: заглавные/строчные, ё/е,
  апострофы (`ko'ylak` = `koylak` = `ko‘ylak`), узбекский кириллицей (`кўйлак` → `ko‘ylak`),
  другие формы слова (`кроссовок` → `кроссовки`). Цвет из запроса («qora krossovka») —
  вещь показывается и открывается в этом цвете. Запрос — в адресе (при «Назад» результаты на месте).
  Ищем на телефоне по списку из `fetchSearchIndex()` (`lib/search.js`); когда товаров станут
  тысячи — перенести поиск в базу.
- **Страница магазина** `/s/<id>`: название, описание, адрес, часы, «Позвонить», карта, Telegram
  и все товары по категориям (кнопки сверху — одна категория, `?c=sneakers`). Фон бежевый.
  Открывается из поиска, по названию магазина на странице категории и из блока «Где купить» у товара.
- Общие детали: строка товара — `components/ProductRow.jsx` (категория, поиск, магазин),
  адрес/часы/кнопки магазина — `components/ShopInfo.jsx` (товар, магазин).
- Шторки снизу (меню категорий, фильтры, сортировка) — один компонент `components/Sheet.jsx`.
  В Telegram его «Назад» при открытой шторке закрывает только шторку (`setTelegramBackButton` в
  `platform.js` помнит, кто открыт последним).
- «Забронировать» на телефоне прилипает к низу экрана.
- **Бронь** (`components/BookingSheet.jsx`, `pages/MyBookings.jsx` — `/bookings`, `lib/bookings.js`):
  - В Telegram: «Забронировать» → шторка (что, цвет · размер, цена, магазин, «держится 2 дня — до …»)
    → «Забронировано!» и **код брони** (6 знаков, покупатель показывает его в магазине).
  - В браузере: шторка «Вход для брони» с кнопкой **«Войти через Telegram»** (`components/TelegramLogin.jsx`)
    → **вход через нашего бота** (см. ниже) → дальше как в Telegram (подтверждение → код). Работает и на компьютере.
    На телефоне ниже ещё ссылка «Или открыть в приложении Telegram» — `t.me/KiyimTopBot?startapp=book__<номер варианта>`:
    в боте та же вещь с тем же цветом и размером и **сразу с подтверждением брони**; после «Забронировать» —
    сразу «Мои брони», новая бронь сверху с зелёной пометкой. На компьютере эту ссылку не показываем:
    Telegram Desktop открывает её с ошибкой `BOT_INVALID`.
    Бронь сама по ссылке **не создаётся** (одно нажатие в боте обязательно): иначе любой, кто откроет
    чужую ссылку, бронировал бы вещь, не зная об этом.
  - **Вход на сайте — через бота** (`lib/auth.js`, `components/TelegramLogin.jsx`, `api/login.js`):
    1) сайт просит у сервера запрос на вход (одноразовый, 10 минут) и показывает **код из 4 цифр** и кнопку —
       ссылку `t.me/KiyimTopBot?start=login_<token>` (такие ссылки открываются и в Telegram Desktop);
    2) в боте «Start» → «Вход на сайт KiyimTop, код на сайте: 4821» и кнопки «Да, войти» / «Отмена»;
    3) сайт раз в 2 секунды (и сразу при возврате на вкладку) спрашивает сервер; после «Да, войти» сервер
       выдаёт **пропуск** (session, подписан сервером, 30 дней) — он хранится в браузере.
    «Мои брони» → «Вы вошли как … · Выйти». Это тот же человек, что в Mini App, — брони общие.
    Запрос на вход создаётся, только когда открыта шторка входа (не при каждом просмотре товара).
    Окошко входа Telegram (`telegram-widget.js`, `/setdomain`) **не используем**: у владельца подтверждение
    от Telegram так и не пришло. Бот всегда переспрашивает «Да, войти?» с кодом — чтобы чужая присланная
    ссылка не впустила кого-то по ошибке.
  - Правила (в базе, функция `create_booking`): не больше **3** действующих броней у покупателя;
    один вариант — одна бронь покупателя; броней на вариант не больше, чем штук в наличии.
    Через 2 дня бронь сама считается истёкшей (отдельная отметка не нужна). Наличие на сайте
    пока не уменьшается от брони: если штуку уже забронировали, второй покупатель увидит «только что
    забронировали».
  - «Мои брони» — меню «⋮» → «Мои брони» и после брони; сначала действующие; отмена — с подтверждением.
  - Ссылка `t.me/KiyimTopBot?startapp=bookings` открывает «Мои брони», `?startapp=<slug>__<id товара>` — товар,
    `?startapp=book__<id варианта>` — товар с подтверждением брони (`fetchVariant()` в `catalog.js`)
    (нужен включённый **главный Mini App** бота: @BotFather → `/mybots` → бот → Bot Settings →
    Configure Mini App → Enable Mini App → адрес сайта; без этого Telegram показывает ошибку `BOT_INVALID`).
- **Сервер** — одна логика в папке `server/`, для любой площадки:
  - `server/handlers.js` — `bookings` (GET мои, POST создать, DELETE отменить), `login` (вход через бота:
    POST — новый запрос, GET `?token=` — «подтвердили?» → пропуск), `botWebhook` (сюда Telegram присылает всё,
    что пишут боту: «Start» по ссылке входа, кнопки «Да, войти» / «Отмена», обычный «Start» → приветствие;
    проверяет секрет Telegram, отвечает всегда 200), `botSetup` (подключить бота к сайту — владелец один раз
    открывает `https://<основной адрес>/api/bot-setup`; повторно — не страшно);
  - `server/telegram.js` — проверка Mini App (`verifyInitData`, 7 дней), пропуск сайта
    (`createSession`/`verifySession`, 30 дней), секрет бота, вызовы Telegram. Шифрование — WebCrypto
    (`crypto.subtle`), а не модуль Node: так работает и в Cloudflare, и в Node;
  - `server/bot-texts.js` — сообщения бота uz/ru (сервер не читает `src/locales`; узбекский — латиница);
  - `server/run.js` — переходник для Cloudflare: `functions/api/*.js` (`onRequest`) — по 4 строки,
    только вызывают обработчик. Новый адрес `/api/…` = обработчик в `handlers.js` + переходник.
  - Адрес сайта для бота — `SITE_HOST` из настроек или адрес, на который пришёл запрос
    (поэтому `/api/bot-setup` открывать на **основном** адресе, не на проверочной ссылке).
  Все ключи для сервера считаются из `TELEGRAM_BOT_TOKEN` (секрет бота, подпись пропуска) — новых не нужно.
  Сайт присылает в заголовке `Authorization`: `tma <initData>` из Mini App или `kts <пропуск>` с сайта
  (`authHeader()` в `lib/auth.js`).
  Без ключей в настройках площадки сервер отвечает «not_configured», а сайт пишет «Бронирование скоро заработает».

### 11. Telegram-бот
- Бот: **@KiyimTopBot** (https://t.me/KiyimTopBot), создан через @BotFather.
- Кнопка меню **«Ochish»** открывает Mini App по адресу https://topdim-self.vercel.app.
  Тот же адрес — у **главного Mini App** (Bot Settings → Configure Mini App): он нужен ссылкам
  `t.me/KiyimTopBot?startapp=…` с сайта. При смене адреса (например, на kiyimtop.uz) поменять его
  в @BotFather в обоих местах: `/mybots` → бот → Bot Settings → Menu Button и Configure Mini App.
- **Бот отвечает на сообщения** через `/api/bot-webhook`. Подключение — один раз открыть
  `https://<основной адрес>/api/bot-setup` (страница напишет «Бот подключён»). При каждой смене адреса
  (Vercel → Cloudflare → kiyimtop.uz) открыть `/api/bot-setup` на новом адресе. Пока бот не подключён,
  он молчит, и вход на сайте не работает.
- **Токен бота** хранится только у владельца. Никогда не просить его в чат и не писать в код.
  Когда понадобится (уведомления о бронях, проверка входа) — владелец сам вписывает его
  в Vercel: Settings → Environment Variables → `TELEGRAM_BOT_TOKEN`.
  Если токен попал не туда — `/revoke` в @BotFather.

### Таблицы в базе
Готовы (`supabase/migrations/`, запускаются по порядку):
- `20261101120000_catalog.sql` — таблицы, правила доступа, 11 категорий.
- `20261101170000_rename_dresses_uz.sql` — «Platya va yubkalar» → «Ayollar ko‘ylagi va yubkalar».
- `20261103120000_shop_district.sql` — район магазина (`district`) для фильтра «Район».
- `20261104120000_bookings.sql` — таблица броней и функция `create_booking` (только для сервера).
- `20261105120000_login_requests.sql` — запросы на вход на сайте через бота (только для сервера).

- `categories` — категории: `slug`, названия uz/ru, эмодзи, порядок. Стартовые 11 категорий.
- `shops` — магазины: название, описание/адрес/ориентир uz/ru, координаты, телефон, Telegram,
  логотип, часы работы, владелец, `is_active` (в каталоге только активные),
  `district` — район Ташкента, одно из 12 коротких имён (`chilonzor`, `mirzo-ulugbek` …;
  список — в `lib/filters.js`, названия uz/ru — в переводах `district.<имя>`).
- `products` — товары: магазин, категория, название/описание uz/ru, бренд,
  для кого (`men`/`women`/`kids`/`unisex`), цена в сумах, фото, `is_active`.
- `product_variants` — размер, цвет uz/ru, количество в наличии.
- `bookings` — брони: магазин, товар и вариант + копия названия/цвета/размера/цены на момент брони,
  покупатель (номер, имя, @username из Telegram), статус (`new` / `confirmed` / `picked_up` /
  `cancelled` / `unavailable`), `expires_at` (через 2 дня), `code` (6 знаков).
  **Посетителям не видна совсем** (RLS без правил, `revoke` у anon/authenticated) — только сервер.
- `login_requests` — вход на сайте через бота: `token` (часть ссылки), `code` (4 цифры), кто подтвердил
  (номер, имя, @username), `confirmed_at` / `cancelled_at` / `used_at`, `expires_at` (10 минут).
  Тоже только для сервера; запросы старше суток сервер удаляет сам.

Будут позже:
- `subscriptions` — подписки магазинов: тариф, оплачено до какой даты.
